# Roadmap after the four-agent review (2026-11-06)

Source: the engineer, ui-dev, release and qa review reports (session scratchpad `reviews.md`). I spot-checked `db.ts`, `store.ts:150-224`,
`sync.ts:20-260`, `types.ts`, `sources.ts`, `build.ts` ids, `vite.config.ts`, `deploy.yml` and `build-cfdict.mjs`.
All findings below are confirmed or plausible. None was refuted.

## 1. Overall verdict

The app is solid. Events are the only truth and replay is deterministic, CI is green, and the UX is mostly good on both devices.
There are no bugs in the common single-tab, single-timezone case. Two edge cases can silently lose reviews: devices in
different timezones, and two tabs on the PC. Three more things can wreck the shared data: a bad Excel import, a renamed
word, and a silent dependency bump. These come first. After them: update delivery to installed apps, then study-flow
polish, then features.

## 2. Strengths

- **Event-sourced core.** Cards come from notes + seeds + events. Replay is deterministic (ties broken by event id, order of arrival
  doesn't matter, and a test proves it). Each device writes only its own log files.
- **Careful sync.** One tree listing per sync. Files are read by blob sha, which avoids the 1 MB limit. Dirty months are
  cleared with compare-then-clear, so offline or failed syncs lose nothing. Linking refuses a public repo, and unknown
  settings fields are kept.
- **Stable identities.** Word ids ignore tones. Events of removed words are kept and come back with the word. The source Excel
  is never written.
- **Lean, secure build.** CSP allows only self and api.github.com. CI has least-privilege permissions. 0 runtime audit
  issues. The precache is small (15 entries), with the 47 MB of strokes and the dictionary in runtime caches.
- **Rich review flow.** Five answer modes, auto-grading with a "Change grade" override, one-step undo, and next intervals
  shown on the grade buttons. Quick memory works well for free practice.
- **Mobile-aware.** Focus mode, desktop sidebar, 16px inputs on touch, reduced motion, and a QR/key onboarding that warns
  that Home Screen storage is separate from Safari.
- **Fast.** Import to Start takes 1.3 s for 1,949 notes. The first card shows in 0.08 s. `deriveCards` takes 0.75 s for 3 years of reviews in
  Node.
- **Healthy baseline.** tsc, 47 unit tests, build, `e2e/offline.py` and `e2e/sync.py` (real file) all pass, with no console
  errors.

## 4. Roadmap

Global rules for every phase:
- **Model tiers:** engineer = opus, ui-dev = sonnet, release = sonnet. Escalate one tier only after two failures.
- **qa:** once per phase batch. Phase 3 can skip qa if it ends up copy and style only.
- **Ownership:** a file belongs to one package among those running in parallel.

### Phase 1: data safety

#### Design decisions

**D1. Event month provenance: `ReviewEvent.mo?: string` (`YYYY-MM`).**
- Own events get `mo = monthKey(t)` at record time. Remote events get `mo` = their file's month at merge time.
- Everything that groups by month uses `monthOf(e) = e.mo ?? monthKey(e.t)`: `markDirty`, `mergeDeviceEvents`, and the upload.
- Merge rule for a file (device X, month M, events E):
  1. Current set = DB events with `dev === X && monthOf(e) === M`.
  2. Delete the ids of the current set that are not in E.
  3. `bulkPut(E.map(e => ({...e, mo: M})))`.

  This merge is order-independent across neighbouring files and no longer depends on the reader's timezone.
- The file format is unchanged: `mo` is never written into files, because the path carries the month. Older clients on other
  devices read our files exactly as before. They keep their own bug until they update, and nothing more can be done about that.

**D2. No Dexie version bump in Phase 1.**
- `mo` is not indexed, and Dexie needs a version bump only when indexes change. A bump would close the IndexedDB
  connection of any old-version tab still open on the PC, and its next review write would throw.
- Instead, a **one-time migration in `store.init`**, guarded by `kv['migr.mo'] = true`:
  1. `db.events.where('dev').equals(me).modify(e => { e.mo ??= monthKey(e.t) })`, which freezes own events in the current timezone.
  2. Delete the `syncShas` entries of *other* devices' `events/…` paths, so the next sync re-reads every remote month file
     once and repairs anything the bug deleted. The re-read cost is one blob read per file, once.
- Also add `db.on('versionchange', () => { db.close(); show "reload" })` now, so future bumps are safe.

**D3. Multi-tab.**
- `syncOnce` runs inside `navigator.locks.request('hz-sync', …)`, and runs directly when `navigator.locks` is missing (iOS before 15.4).
- The upload reads `db.events` for this device and month. Merges read "current" from the DB, not from memory.
- After any local write (review, undo, merge, vocab, settings), the tab posts on `BroadcastChannel('hz')` `{ what }`. Other
  tabs call `reloadFromDb()`, debounced 300 ms.
- An old-version tab doesn't take part in any of this. That window closes once Phase 2's reload flow ships.

**D4. Dirty stamp and atomicity.**
- `recordReview` puts the event and updates `kv.dirty` in **one** `rw` transaction over `[db.events, db.kv]`.
- The stamp is `Math.max(Date.now(), lastStamp + 1)`. It stays timestamp-like, so an old tab comparing with `Date.now()` still errs
  toward re-uploading.

**D5. Per-file isolation.**
- Each remote file (and each of vocab and settings) is parsed and merged inside its own try/catch. A failed file keeps its
  old known sha, so it is retried next time.
- Steps 4–6 (push) always run. `SyncInfo` gets `warnings?: string[]`.
- Rebuild once after all merges: `mergeDeviceEvents` gets a `{ rebuild: false }` option, and the caller runs `rebuildAll()` at the end.

**D6. Bad-import guard.**
- A pure function `checkImport(prev, next)`. It holds the import when any of these is true:
  - `next.notes.length < 0.8 × prev` and the drop is ≥ 20 notes;
  - a sheet that had notes is now `skipped` or missing;
  - a sheet lost more than 50% of its notes.
- A held import is stored in `kv.pendingImport` (the full VocabFile plus reasons), with nothing applied and nothing marked dirty.
  Hugo then picks Keep the old list or Use the new one. A rejected hash is remembered (`kv.rejectedImportHash`), so the folder
  watcher doesn't ask again until the file changes.
- The guard applies only to local imports. Vocab arriving through sync was already accepted on its device.
- Old app versions on the PC have no guard until they update. Ship Phase 1 and Phase 2 close together.

**D7. Word renames: `VocabFile.aliases?: Record<oldNoteId, newNoteId>`.**
- This is an additive optional field, and `version` stays 1.
- Detection runs on the main thread in `importBytes` (it has the previous notes). A pair matches when the old id is absent from
  the new notes, the new id is absent from the old notes, and both have the same kind. Then:
  - vocab: same `hanzi` and the same `refs[0]` sheet + (row or ID cell);
  - grammar: same sheet + (row or ID cell).

  Only unique 1:1 matches count.
- Aliases accumulate across imports. A seed moves to the new id when the new id has none.
- Resolution happens in **memory only**:
  - `state.events` becomes an alias-resolved *view* (the `card` prefix is rewritten). DB rows and uploaded files keep raw
    events, and uploads read the DB (D3), so events are never rewritten.
  - An alias is ignored when its source id is a current note again (the rename was reverted). Chains are followed up to a depth of 10.
- When synced vocab arrives without `aliases` (an old client imported), keep the union with the local aliases.
- On old clients, a renamed word shows as new until they update. History is not lost.
- The import report lists the detected renames.

**D8. Forward compatibility and pinning.**
- `decodeEvents` maps columns by the `fields` header.
- A vocab file with `version > 1` is not applied, and the warning "Update the app to read this word list" is shown.
- A truncated tree listing throws a clear error.
- `ts-fsrs` is pinned to `6.0.0`. A golden test replays fixed events and compares them with a snapshot of card states,
  so any future bump that changes scheduling fails CI.

### Phase 2: reliability and deploy

**Design decisions:**
- **Update flow: keep `skipWaiting` and `clientsClaim`, and do the registering ourselves.** Switching to `registerType: 'prompt'`
  would leave the very first transition waiting forever on iOS Home Screen apps, because the old code never sends
  SKIP_WAITING. Instead:
  - `injectRegister: false` and `navigator.serviceWorker.register(BASE + 'sw.js')`.
  - When `controllerchange` fires and a controller existed at boot, the app shows "New version, Reload".
  - It reloads automatically when it becomes visible again, if the route is not `review` or `quick` (cards). Every answer is
    already saved per card, so a reload only risks the card on screen.
  - `reg.update()` runs on `visibilitychange` (throttled to every 30 min) and at boot.
  - No CSP change.
- **CFDICT:** when `process.env.CI` is set and there is no dictionary, exit 1, so the old deploy stays live. Sanity check:
  more than 50k lines, or exit 1. Workflow: `actions/cache` on `public/dict`, keyed on `hashFiles('scripts/build-cfdict.mjs')`
  plus the year-month. Committing a copy is not needed.
- **e2e in CI:** a new `e2e` job (needs: build, gates deploy). It runs `pip install playwright`, then
  `python -m playwright install --with-deps chromium`. That is fine in CI; the rule against `playwright install` covers only cloud
  sessions. The job then runs `vite preview` and `offline.py`, and `sync.py` against a **synthetic workbook generated at runtime** by
  `e2e/make_sample.py` (about 30 common HSK1 words, two green rows, one grammar sheet; never committed, since `*.xlsx`
  is git-ignored). Remove `e2e/**` from `paths-ignore`.
