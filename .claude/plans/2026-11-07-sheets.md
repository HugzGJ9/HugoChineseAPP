# Sheets: "my Excel, with a bit more design" (2026-11-07)

## Goal
The home screen becomes **Sheets**: one tab per Excel sheet, rows in Excel order, hanzi / pinyin / meaning with Quick
memory's hide/show, and a status per row that Hugo sets himself (Mastered, Not known, Studying, Not studied). Statuses start
from his Excel colours. His own changes win when they are newer. On the PC the app writes them as fills into a **copy** of his
workbook, and it never touches the original. Every row has a writing area: typed pinyin or hanzi, a stroke-checked drawing,
and a free scratch pad.

## 1. Decisions

**D1. Status model (`WordStatus`), separate from FSRS.**
```ts
export type WordStatus = 'new' | 'studying' | 'notknown' | 'mastered';   // UI: Not studied, Studying, Not known, Mastered
```
- Excel colour → status, with `colourStatus(sheet, colour)`:
  - On a sheet whose `sheetTag(name) === 'HSK4'` (HSK四级), every row is `mastered`, whatever its colour.
  - On every other sheet, `generalColourStatus(colour)` applies:
    - `isGreen` (A9D18E, C5E0B4 and other greens, reusing build.ts) → mastered.
    - Yellow (FFFF00, FDF95F, plus a hue check of 45–65° with s ≥ 0.6 and l ≥ 0.5) → notknown.
    - None or FFFFFF → new.
    - Any other colour (FF0000, 8FAADC, EEA6A6, 7193FF…) → studying.
- **FSRS stays as an optional tool and is never shown as "status".**
  - Review, Quick's "send missed to reviews", events and `deriveCards` are unchanged.
  - The new status marks are no-ops in the engine, because `applyMark` has a `default` branch, so the golden snapshot
    is unchanged.
  - Review is reached from Sheets ("Review these": a custom `#/review?cards=` session for the visible rows) and from a
    small "Due reviews (N)" link.
  - Practising never changes a status (D8).

**D2. Status changes are marks with new kinds. They reuse marks/<device>/<month>.json, kv and sync, with no format change.**
- `MarkKind` gains `'st:new' | 'st:studying' | 'st:notknown' | 'st:mastered'`. `setNoteStatus(noteId, STATUS_MARK[s])`
  already exists in store.ts and is reused as is. Undo uses `undoMark`.
- Why new kinds instead of reusing `known`/`relearn`: old and current engines turn `known`/`relearn` into FSRS schedule
  changes. Hugo does not want status to drive intervals.
- Legacy marks are still read as statuses: `known` → mastered and `relearn` → notknown. So the "I know this" marks he set
  in the last batch keep showing as Mastered.
- Compatibility of the deployed client (117c8eb), checked in its code:
  - `decodeMarks` keeps an unknown `a` (it checks only that it is a string).
  - `latestMarks` ignores it.
  - `applyMark` falls to `default: return s`.
  - progress.ts and stats `markCounts` look only at the known/relearn/suspend slots.
  - Words.tsx shows the raw kind (`st:mastered`) in its History table. That is cosmetic, until that device updates.
  - Older clients don't read `marks/` at all.
  - So no client misapplies these marks. Marks stay on the **note**: every row of that word changes (Q3).

**D3. "His change wins if newer": per-row colour time, `VocabFile.colourSince`.**
```ts
colourSince?: Record<string /* rowKey */, [WordStatus, number]>   // rowKey = `${noteId}@${sheet}#${k}`, k = nth ref of that note in that sheet
```
- Computed on the importing device in `prepareImport` (guard.ts), where renames are known, by
  `colourSinceFor(notes, prev?.colourSince, renames, t)`:
  - The same status as before keeps the old time. A changed status or a new row gets
    `t = min(source.modified || importedAt, importedAt)`.
  - When there is **no previous map at all** (first import with this version, or a list written by an old client), every
    row gets `t = 0`, so existing marks win and nothing he set is overridden.
- Effective row status: the latest status mark of the note (alias-resolved `state.marks`) wins if `mark.t > since`.
  Otherwise the row's colour status applies.
- Additive field inside `vocab.json.gz` (version stays 1). Old clients ignore it. `setVocab` keeps the local `colourSince`
  when an incoming list lacks it, the same way aliases are kept today.
- Per-note status (Quick filter, Words detail): a winning mark if there is one. Otherwise the row with the latest `since`,
  with ties going to the later sheet (`order`).

**D4. Per-row colour in the import (additive).**
- `SourceRef.colour?: string` holds the same value `rowColour()` gives today: the first non-white fill of the hanzi or ID
  cell. It is set per ref, so a word merged across HSK四级 and HSK五级 keeps both colours. `Note.colour` is unchanged.
- Fallback for lists from old clients: `ref.colour ?? (refIndex === 0 ? note.colour : undefined)`.
- `SheetReport.cols?: SheetCols` lets the copy writer find the cells to restyle without re-parsing values:
  ```ts
  export interface SheetCols { id?: string; hanzi?: string; first: string; last: string; status: string[] }
  ```
  - `first` and `last` are the header row's text columns.
  - `status` is the set of columns whose fill equals the row colour in at least 50% of the sheet's coloured rows. The
    fallback is `[id, hanzi]`.
  - On Hugo's real file this gives A–B for HSK四级 (ID and hanzi coloured, C–D white) and A–D for HSK五级.
- The notes hash changes once (ref.colour), so the PC re-pushes the vocab once. That is expected.
- No Dexie bump: notes rows get only a nested additive field, with no new index.

**D5. The workbook copy (PC, linked OneDrive folder).**
- The copy is named `<stem> (app).xlsx` (`Hugo_chinese_vocab (app).xlsx`) and is written next to the original. The original
  is only ever read. `checkFolder` looks up `settings.fileName` exactly, so the copy is never imported.
- The copy is **rebuilt from the original's bytes every time** (stateless). Only rows whose effective status differs from
  their colour status are patched (`copyFills`).
  - A row is skipped when its current colour already expresses the target under the general rules. For example, a pink
    row stays pink for Studying.
  - Target fills: Mastered A9D18E, Not known FFFF00, Studying 8FAADC, Not studied = no fill.
  - HSK四级 rows are untouched unless he sets something other than Mastered.
- Which cells change in a patched row:
  - Cells in `[first..last]` whose resolved fill equals the row's current colour (`RowFill.from`). This preserves his
    style: whole row on HSK五级, ID and hanzi on HSK四级. Other cells (red E–F notes, black C–D on blank rows) stay as they are.
  - If the row has no colour, the sheet's `status` columns change. A missing `<c>` is inserted in column order as
    `<c r="X12" s="N"/>`. The base style is the row's `s` when `customFormat="1"`, else 0.
- XML patching, in a worker (`patch.worker.ts`), with fflate:
  - **styles.xml**:
    - Reuse a solid fill whose fgColor resolves to the target, or append
      `<fill><patternFill patternType="solid"><fgColor rgb="FFxxxxxx"/><bgColor indexed="64"/></patternFill></fill>`.
    - Clone the cell's `<xf>` (attributes and children such as `<alignment>`), with `fillId` replaced and `applyFill="1"`.
      The clone is memoised by (xf, fill).
    - Update both `count` attributes.
  - **sheet XML**:
    - One forward pass over the string: `indexOf('<row r="N"', pos)` with the targets sorted. Output is an array of
      untouched slices plus edited `<row>` elements, joined once.
    - Only the `s` attributes of the targeted cells change.
    - sheet2.xml (11.6 MB, 520k mostly empty styled cells) is never regex-scanned as a whole.
  - Every other entry keeps **identical content** and the original entry order. The zip container is re-deflated
    (fflate `zipSync`, level 6). Raw-copying the compressed entries isn't worth a custom zip writer: Excel only reads the
    content.
  - Safety check: each target row's hanzi cell text (shared strings or inline) must contain `RowFill.hanzi`. If any row
    fails, the copy is **not written** (`WorkbookChangedError`), and a forced re-import runs.
  - The copy is written only when the original's `name|lastModified|size` equals `meta.source`, so the rows match this exact
    file.
- Triggers:
  - Marks change: 4 s debounce.
  - Import applied: 1 s.
  - Vocab from sync: 4 s.
  - Tab hidden: flush now.
  - Window focus after a failed write: retry.
  - Start-up: write once.
  - Skipped when `kv.copySig` (`fileSig|fnv1a(JSON(fills))`) is unchanged and the copy exists.
  - If `meta.report` has a sheet with `cols` missing (a list imported by an older version), start-up runs `checkFolder(true)`.
- Errors, handled as progress.ts does today:
  - `NoModificationAllowedError` / `InvalidStateError` → "Hugo_chinese_vocab (app).xlsx is open in Excel. Close it and the
    app updates it on the next change."
  - `FolderInfo.written` / `writeError` now describe the copy.
- **Hugo_chinese_progress.xlsx is no longer written** (Q2). folder.ts stops calling `writeProgress`. progress.ts and its
  tests stay dormant this batch, and the old file is left for Hugo to delete.
- iPhone: no File System Access, so statuses set there reach the copy the next time the PC app syncs.

**D6. Sheets screen, which reuses Quick memory.**
- Quick's hide/show pieces move to `src/ui/qm.tsx`, and Quick.tsx keeps working through them:
  - `Layer`, `Shown`, `PRESETS`, `LayerBar`, `useHold`, `useShift`, `QmList`/`QmRow`.
  - `QmList` becomes generic over `{ key, note }` items. Peek state is keyed by `key`, because one note can have two rows
    in a sheet.
  - It gains optional `lead`, `trail`, `rowClass` and `onKey` render props.
- Tabs come from `meta.report` in workbook order, keeping the sheets that have rows in `sheetRows`. HSK四级, HSK五级, Measure
  words, 语法 and Suddently show; EXAM is skipped. Rows are sorted by `ref.row`.
- Grammar is just its sheet: the pinyin column is hidden when the whole tab has no pinyin, and the meaning column holds
  the explanation.
- Nav = **Sheets · Quick · Settings**.
  - The default route becomes `sheets`.
  - `#/today`, `#/stats`, `#/words`, `#/grammar` and `#/report` stay as routes, linked from a "More" block in Settings.
  - Today's notices (pending import, folder permission, sync error, fixes, backup nudge, empty state) are exported and shown
    on Sheets, so none are lost.
- **Setting a status:**
  - Tapping a row's status chip opens a 4-choice menu, and the choice applies at once.
  - A **Paint** toggle (pick a status, then each chip tap applies it) gives true one tap per row (Q1).
  - An inline "Undo" bar follows each change.
  - On PC, keys act on the focused row: `m` Mastered, `k` Not known, `s` Studying, `u` Not studied, `w` practise, `/` search.
- Search matches hanzi, alts, toneless pinyin and meaning (en/fr/frAuto) in the current tab, with "also in <sheet> (n)"
  chips. The status filter (All plus the 4 statuses, with counts) is a per-device pref (`sh.tab`, `sh.filter`, `sh.shown`,
  `sh.paint`). These are backed up through a new `sh.` device prefix and not synced.

**D7. Quick and Words follow the new statuses.**
- Quick's status filter becomes: Any · Not studied · Studying · Not known · Mastered · Seen this week · Missed recently. A
  stored `studied`/`new` value reads as `all`. Old clients given a new value simply don't filter, which is harmless.
- In the Words detail, "I know this" and "Relearn" are replaced by the 4-status picker. Suspend stays. History labels the
  `st:*` kinds.

**D8. Writing area.**
- Each row has a pen button that opens a practice panel: a right side panel on wide screens, a bottom sheet on phones.
- Modes:
  - **Pinyin**: shows hanzi and meaning, `checkPinyin`.
  - **Hanzi**: shows pinyin and meaning, `checkHanzi`, `lang="zh-CN"` input.
  - **Draw**: `WritePad`, outline on or off, `StrokeAnimation` on reveal.
  - **Free pad**: a canvas, no grading, optional 田字格 grid. It is also reachable from the Sheets toolbar.
- Grammar rows get Free pad only.
- No review events are recorded and the status never changes automatically. The panel's footer has the one-tap status
  picker.

**D9. iPhone, PWA, CSP.**
- Inputs are 16px with `autocapitalize="off" autocorrect="off" spellcheck={false}`.
- The bottom sheet pads `env(safe-area-inset-bottom)` and caps at `92dvh` with internal scroll.
- The canvas uses `touch-action: none` and DPR scaling.
- The sticky tab strip scrolls sideways inside itself, with no page overflow.
- Everything works offline: Sheets is local, and stroke data uses the existing cache.
- The new worker chunk is precached by the existing `**/*.js` glob, and `worker-src 'self'` already allows it. There are no
  new hosts, assets or dependencies.

## 2. Questions for Hugo
1. **One tap per row: is a 4-choice menu (tap the chip, tap the status) plus a "Paint" mode (choose a status once, then one
   tap per row) right?** Default: both.
2. **Should the app stop writing Hugo_chinese_progress.xlsx, now that the (app) copy carries your statuses?** Default: yes,
   stop. The old file stays until you delete it.
3. **A word that is on two sheets (for example HSK四级 and HSK五级): one status for the word, so both rows change?** Default:
   yes (per word).
4. **Which file do you edit in Excel from now on?** Default: the original. The (app) copy is rebuilt by the app each time,
   so anything typed into the copy is lost. If you'd rather work in the copy, the design changes: the app would have to
   read it back.
